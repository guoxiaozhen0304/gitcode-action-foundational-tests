## 失败分诊 · REL-K8S-01-051 · 同一集群重复接入的幂等性

**判定结果**: SKIP（无法脚本化执行）
**根因初判**: 平台能力边界 — 当前测试 infrastructure 无法自动化此场景
**责任人**: 多方联合（Phase 02 扩充自动化能力 + 平台补全 API）

**证据**:

- **SKIP 原因**: 用例需要在真实 K8s 集群上执行重复接入操作（≥2 次）并验证幂等性（资源数不虚增、运行中任务不中断），无标准化平台 API 支持此类操作
- **具体阻塞点**:
  ```yaml
  # 当前 YAML 的特征:
  workflow: null
  trigger:
    event: manual
    params:
      platform_op: cluster_re_onboarding
  variables:
    repeat_onboarding_times: ">=2"
    running_task_present: "true"
  assertions:
    target: running_task_impact
    eval: llm_assisted
  ```
- **对照 VALIDATION-RULES.md**: 此类用例依赖平台级集群重复接入操作 + 幂等性验证，不在当前 Phase 02 脚本化能力范围内

**置信度**: 高

**影响**:
- **阻塞性**: 🔴阻塞 — 无法通过 API 脚本化重复接入集群
- **静默性**: 🟡可察觉 — 分类阶段明确标记为 SKIP
- **影响面**: 🟢单用例 — 仅此场景受限于集群接入幂等性验证
- **综合**: 需要平台提供集群接入/移除 API 并完成 ≥2 次重复操作验证
- **是否有规避手段**: 否 — 需平台提供集群接入管理 API

**建议**:
- 平台提供集群接入/移除的 REST API
- Phase 02 扩展 harness：集成集群管理 API 调用能力
