# 质量门禁（全平台 — 定义「凭什么敢上线」）

> L0 基线之一。定义分维度阈值与 blocker 判定规则，是第二部分报告分维度聚合与门禁判断的依据。
> **本文件已按全平台扩展，阈值需阿蓁按实际业务调整。**

## 分维度门禁

| 维度 | 上线阈值 | blocker 判定 | 备注 |
|---|---|---|---|
| **完备性** | Parity Matrix 中 P0 能力项 100% 有用例且通过；无「未知」阻塞项 | 任一 P0 能力项不支持或行为错误 | 覆盖 API + Git + MR + Issues + Packages + 权限 |
| **兼容性** | 所有一致性用例（应与 GitHub 一致者）通过；差异确认用例均已文档化 | 存在未声明的破坏性差异 | 重点关注 Actions 迁移差异 |
| **稳定性** | P0 稳定性用例全过；故障注入均满足恢复预期 | 故障后无法恢复 / 数据损坏 | 含并发、速率限制、大文件、Webhook |
| **安全性** | **全部 negative 断言必须通过，零容忍** | 任一 secret 泄露 / 权限越界 / 注入成功 | 覆盖 Actions、权限、Package、Webhook |
| **易用性** | P0/P1 错误信息类用例达标；核心迁移路径可跑 | 核心迁移路径完全不可用且无提示 | 含文档一致性、通知、错误信息质量 |

## 全局 blocker 规则

1. **安全零容忍**：任一安全 `negative` 断言失败 → 直接 blocker，不可上线。
2. **覆盖盲区**：任一风险登记册 blocker 风险项无 P0 用例覆盖 → 门禁不通过。
3. **核心链路不可用**：以下任一链路完全中断 → 直接 blocker：
   - Git Clone/Push 不可用
   - API 鉴权完全失效
   - MR 创建/合并不可用
   - Package 上传/下载不可用
4. **DoD 未全绿**：该批次不予交付第二部分。

## 分维度通过率阈值（供 report_builder.py 参考）

| 维度 | 建议阈值 | 说明 |
|---|---|---|
| 完备性 | 95% | P0 必须 100% |
| 兼容性 | 90% | 允许已文档化的差异 |
| 稳定性 | 85% | 故障注入允许单次失败 |
| 安全性 | 100% | negative 断言零容忍 |
| 易用性 | 80% | P0 必须 100% |

## 判定输出约定

第二部分按维度聚合用例结果，对照本门禁产出「通过/不通过 + blocker 清单」。
本部分只定义规则，不执行判定。

> **填写建议**：阈值应与风险登记册 blocker 列表一致；安全维度保持零容忍。阿蓁可根据实际上线节奏调整阈值（如内测期可放宽至 80%，生产环境必须 95%+）。
