# UI-ISSUE-25-002

## 基本信息
- **ID**: UI-ISSUE-25-002
- **维度**: usability
- **优先级**: P0
- **标题**: Issue 列表筛选与排序交互响应验证
- **Intent 溯源**: INTENT-USE-002

## 测试目的
验证 Issue 列表页的筛选器和排序选项能即时响应，且筛选状态在页面刷新后保持。

## 前置条件
- 用户已登录
- 目标仓库存在多条不同状态（开启/关闭）的 Issue

## 操作步骤
1. 打开仓库 Issue 列表页 `/{owner}/{repo}/issues`
2. 在筛选栏选择 "已关闭" 状态
3. 等待列表刷新，观察 URL 是否携带状态参数
4. 点击 "最新更新" 排序选项切换排序
5. 刷新页面

## 预期结果
- 筛选后列表仅展示关闭状态的 Issue
- URL 中带有状态参数（如 `?state=closed`）
- 排序切换后 Issue 顺序随之改变
- 刷新页面后筛选与排序状态保持

## 清理
- 无需特殊清理（teardown.reset: none）
